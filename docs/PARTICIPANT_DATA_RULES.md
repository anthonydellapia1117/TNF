# Participant data rules

Owner: Anthony DellaPia.

## Shared email addresses (rule set 2026-08-24)

A shared email between two participants is worth noting but is **not by
itself a duplicate signal**. People in this pool share addresses — spouses,
business partners, friends who let one guy handle the email. Treat a shared
address as **informational, never as a merge candidate**:

- The admin Emails screen marks a shared address with a muted "shared ×N"
  chip — plain information, no warning styling, no merge suggestion.
- A shared address goes into the copied BCC list once, not once per person.
- Merging two participant rows requires the owner confirming they are the
  same person — a matching email alone never justifies it.

Precedent: Frank Animal and M & M both use bobm@mmelectrical.net. Confirmed
by Anthony (2026-08-24) as two separate people, both friends of Scro, using
one shared contact address. Two rows, two blocks, one email — and that is
fine.

## Prior-season data: identity, never state (rule set 2026-09-03)

**A prior season is a source of IDENTITY. It is never a source of STATE.**

Who someone is carries forward. What they have done this year does not.

**Identity — safe to carry forward:**

- Display alias
- Email address

The 2025 grid was used exactly this way and deliberately: it filled 17
aliases and 8 email addresses that no 2026 message contained.

**State — never carried forward:**

- Owner group
- Block number
- Block count
- Payment status

Each of these must come from a **2026 source**: a message from the person, a
relaying owner Anthony names, or Anthony directly. A prior-season value is
not a 2026 source no matter how confidently it is stated.

A prior-season value **may** be recorded in notes as context — that is
history, and history is worth keeping. It is never written into a state
field on its own authority, and it is never cited to Anthony as the current
value.

### Precedents

- **Block number — Anthony Esgro, 2026.** His email listed blocks 8, 17, 27,
  47, 85 and 5. It was a verbatim copy of his 2025 grid rows, not a set of
  fresh requests. Four blocks had to be released and their holders redrawn.
  See `BLOCK_ASSIGNMENT_POLICY.md` Rule 1.
- **Owner group — Eric Speca, 2026.** He was RM in 2025. In 2026 he emailed
  Anthony directly with no intermediary, so he came in as DIRECT, which
  later retired into AVD. His current group is **AVD**. The 2025 group was
  relayed as if it were current, and it was wrong.

The two failures are the same failure on different fields. Expect a third
one on a field not yet listed: the rule is the general form, and the list of
state fields is not a closed set. If a field describes what someone did this
season, it is state.
